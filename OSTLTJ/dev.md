# OSTLTJ App 研究與功能分析

此文件記錄了 `/OSTLTJ/index.html` (「指向耶穌的大故事：358 天讀完整本聖經」) 的核心功能與架構分析，作為未來改進與優化此 App 的討論基礎。

## 1. 系統架構與前端技術
- **單頁式應用 (SPA)**：所有 UI 邏輯與互動皆在 `index.html` 內透過 Vanilla JavaScript 處理。
- **樣式與 UI**：使用 Tailwind CSS 進行快速與響應式排版，搭配 Lucide Icons 作為圖示庫。
- **資料處理**：使用 `PapaParse` 極速解析 CSV 檔案 (元數據、翻譯計畫、影片連結等)，並使用原生 `fetch` 載入 JSON (聖經經文庫)。
- **PWA (漸進式網頁應用)**：支援 Web App Manifest (`manifest.json`) 與桌面安裝提醒，並實作針對 iOS Safari 及各系統的「安裝至主畫面」教學 Modal。

## 2. 核心功能模組

### A. 初始設定精靈 (Setup Wizard)
- 首次使用時跳出，引導使用者建立新的讀經計畫或匯入舊有進度。
- **開始日期設定**：設定計畫的起點，系統會自動推算每天對應的真實日期。
- **放假日設定**：允許使用者每週選擇 1~2 天作為「放假日」，系統推算進度時會自動跳過這些日子，重新計算「預計完成日期」。

### B. 讀經面板與進度追蹤
- **天數切換**：提供 Day 1 到 Day 358 的進度導覽，可透過上一天/下一天按鈕或輸入數字跳轉。
- **智慧定位載入**：啟動時會自動判斷目前日期與未讀天數，載入最適當的進度頁面，避免使用者產生進度落後的焦慮感。
- **打勾完成機制**：每頁有「標記為已讀」功能，打勾後 1 秒會觸發「智慧跳轉」，自動前往下一個未讀天數。
- **100% 完讀獎勵**：完成 358 天進度後會彈出恭喜視窗，並引導開啟下一輪計畫。

### C. 內容顯示區塊 (四大卡片)
1. **引導短文 (Devotional/Intro)**：提供每日經文的脈絡與介紹。支援「檢視原文」連結至 BibleProject 官網。
2. **輔助影片 (Videos)**：嵌入 YouTube 影片，支援中英文版切換。若有需要，會顯示「老張批註」提供額外見解。
3. **今日經文 (Scripture)**：
   - 即時將 CSV 設定的經文範圍 (如 `創1:1-10`) 映射至 `rcuv.json` (和合本修訂版) 並動態渲染。
   - 支援雙語對照：可一鍵顯示 ESV 英文譯本 (`esv2016.json`)。
   - 註釋系統：經文內的 `?註：...?` 會被轉換為可點擊的浮動註釋 (Footnote Modal)。
4. **反思問題 (Reflection)**：每天提供幾題反思問題，幫助消化吸收。

### D. 默想筆記功能 (Meditation Notes)
- 讓使用者在每日頁面下方紀錄心得、感動或禱告。
- 點擊「儲存」後，資料存放於本地端 `localStorage`。

### E. 語音朗讀系統 (TTS - Text to Speech)
- 利用瀏覽器內建 `SpeechSynthesis` API 實作全域或分段語音播放。
- **優化與防呆**：
  - 過濾並挑選高品質中文語音 (如 HsiaoChen 等 Premium 語音)。
  - 支援語速調整 (0.8x 到 1.5x)。
  - **分段發音與巨觀捲動**：解決長文語音中斷的問題，朗讀時會自動捲動畫面至對應段落 (Macro Scrolling & Micro Scrolling)。
  - **一鍵全部朗讀**：會自動接力播放「引導短文 -> 經文 -> 反思問題」，甚至用語音提示觀看影片。
  - **全域播放控制**：提供統一的「播放 / 暫停 / 繼續 / 停止」狀態連動 UI，避免多個聲音重疊衝突。

### F. 資料備份與還原
- 完全依賴瀏覽器的 `localStorage` 儲存狀態，無後端資料庫。
- 儲存的鍵值包含：`gemini_start_date`, `gemini_read_progress`, `gemini_rest_days`, `gemini_meditation_notes` 等。
- **匯出 / 匯入 JSON**：可將所有進度打包為 JSON 檔下載備份，或上傳還原。
- **雙層重置防護**：重置系統時，提供「保留默想筆記」或「完全清空」的選項。

### G. 其他輔助功能
- **新手導覽 (Tour)**：使用 `driver.js` 提供互動式介面導覽。
- **問題回報**：帶有專案參數與環境參數 (OS/Browser) 的 Google 表單連結。
- **防禦機制 (In-App Browser)**：自動偵測 LINE/FB 內建瀏覽器並提示跳出，確保資料不會因清除快取而遺失。

## 3. 未來改進與優化潛力 (討論方向)
*   **模組化與框架化**：目前的單頁 Vanilla JS 已達 2300 行，未來若需新增功能，可考慮重構為模組化 (ES Modules) 或導入輕量級框架 (如 Vue、React 或 Svelte)，以提升維護性。
*   **狀態管理優化**：大量依賴全域變數與 DOM 操作，若重構，可建立集中的狀態管理。
*   **同步與雲端儲存**：目前僅依賴 LocalStorage 且需手動匯出/匯入備份。若有跨裝置需求，可評估整合輕量級的 Backend-as-a-Service (如 Firebase) 提供登入與雲端同步功能。
*   **UI/UX 美化**：目前的 Tailwind CSS 設計已相當完善，但可依據新的設計規範進一步強化微動畫 (Micro-animations)、暗色模式 (Dark Mode) 或是更豐富的過場效果。
